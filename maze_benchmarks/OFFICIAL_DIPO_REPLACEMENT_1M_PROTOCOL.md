# Original MuJoCo DIPO baseline replacement

The previous PointMaze/Way `dipo` jobs in frozen source `a55aaf13f7803b5cf8da7ba56f318675c7794171` instantiate `antmaze/ddiffpg/algo/dipo.py`. That is a five-step diffusion DIPO variant, but it is not the separately pinned MuJoCo implementation used in this repository's GMM40/navigation comparisons. Keep those results and their raw trajectories under their original source commit; do not relabel them as BellmanTimeHut/DIPO. In particular, the prior serialized Hydra `act_class=TanhMLPPolicy` is misleading: `ActorCriticBase` overrides it and builds `DiffusionPolicy` for `name=DIPO`.

This fresh seed-0 replacement pins `gmm40-baseline/DIPO` at `c6d8d1b39d6cea22e7d779e08111dbf974dbb4fc` and invokes its `agent.DiPo.DiPo` without editing the upstream submodule. It uses the original cosine-schedule, 100-step diffusion actor, twin scalar-Q critic, 20 Adam action-gradient steps at LR .03, actor/critic Adam LR 3e-4, target tau .005, gamma .99, ratio .1, and gradient limit 2. The original `DiffusionMemory.replace` uses `np.copyto` on an advanced-indexed temporary; the local vector adapter uses indexed assignment to persist the improved actions, as in `gmm40/navigation_agents.py`. Replay, diffusion-memory, optimizer, actor/critic/target, and source provenance are kept separate from earlier jobs.

Use the existing unmodified maze tasks, sparse +100 PointMaze success and wall-free Way reward. The shared comparison profile stays 256 environments, batch 4096, 16 learner updates per 256 transitions, warmup 8192 included in 1,000,192 total transitions, seed 0, evaluation every ~200k (200 episodes), and final PointMaze 500/Way 1024 episodes. Original DIPO's MuJoCo default is batch256 and one learner update per environment transition; this shared fast profile is an explicit benchmark adaptation, not a paper-exact DIPO reproduction. The 100 diffusion reverse steps make it substantially slower than the five-step DDiffPG variant; no 16:00 completion guarantee is implied. Each job runs an 8448-transition/16-update GPU preflight before 1M training. Use independent GPU-lock guarded workers, no automatic retries, and preserve both campaigns.

Evaluation samples fresh initial Gaussian action noise at every action and disables only reverse-process noise (`eval=True`), matching the pinned MuJoCo implementation. The official algorithm has no entropy objective; high success on one goal does not imply policy multimodality. Report per-goal counts and individual trajectories as well as total success, with the corrected implementation and previous variant distinguished by source.
